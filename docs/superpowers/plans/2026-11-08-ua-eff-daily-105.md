### Task 2b: Joint UA + gains daily fit (amendment, owner click 2026-11-08 after the Task 4 gate returned STOP)

**Why:** gate (Task 4, `docs/analysis/2026-11-08-cop-scale.md` "#105 physics gate") — the through-origin daily fit has no gains term while `_space_heating_kwh` subtracts `Q_base_el·internal_gains_fraction` (gains counted twice), and the data has a balance point (linear intercept fit: G ≈ 1.0 kW / UA ≈ 155 W/K with the old formula; G ≈ 1.4 kW / UA ≈ 220 with the heating refit). UA drifted 50→93 W/K across origins; MAE 60–84 % of the meter mean.

**Files:** `apps/energy_forecast/physics.py` (`_calibrate_ua_eff_daily`, `calibrate()`, `recalibrate_ua`, `_space_heating_kwh`), `apps/energy_forecast/const.py`, `tests/test_physics.py::TestUaEffDaily`.

**Design:**
- Fit the **same clipped hourly model prediction uses** (ignoring `q_mass`, which sums to ≈ 0 per day, and `solar_gain_area`, which is 0 live): per eligible day d, `kwh_d ≈ Σ_h max(0, UA·ΔT⁺_h − G) / COP_h / 1000`. Two parameters UA (W/K) and G (W, ≥ 0), solved with `scipy.optimize.least_squares` (bounds UA ∈ [0, UA_EFF_SANITY_MAX_W_PER_K], G ∈ [0, UA_EFF_DAILY_MAX_GAINS_W]); initial guess from the linear fit `kwh = UA·Σ(ΔT⁺/COP)/1000 − G·Σ(1/COP)/1000`, G clamped to ≥ 0. If scipy is unavailable, fall back to that linear fit (clamped). R² = 1 − SSE/SST on daily kWh with the fitted model.
- Rejection unchanged (UA ∉ [50, 500] or R² < 0.4 → None) plus G at its upper bound → None with a warning ("gains at bound").
- `const.py`: `UA_EFF_DAILY_MAX_GAINS_W = 3000.0`.
- `_calibrate_ua_eff_daily(...) -> tuple[float | None, float | None, int]` returns `(UA, gains_w, n_days)`; update all callers and existing tests.
- `calibrate()` / `recalibrate_ua()` store `_calib["gains_w"]` (None when UA is None or method is hourly).
- `_space_heating_kwh`: `q_gain_int = gains_w` when `_calib.get("ua_eff_method") == "daily"` and `_calib.get("gains_w") is not None`; otherwise today's `Q_base_el·internal_gains_fraction·1000`. Keyed on the stored calibration method (what produced UA), not the config flag.

**Tests (RED first):**
- `test_joint_fit_recovers_ua_and_gains`: fixture with daily-mean T_out spanning 2–14 °C (e.g. `2 + 12·(day % 7)/6` plus a ±4 K diurnal sine), T_in 20, meter generated hourly as `max(0, 150·ΔT − 1000)/COP/1000` then moved into 2-h daily bursts (as `_meter_for`) → UA ≈ 150 (rel 0.05), G ≈ 1000 (rel 0.1).
- `test_zero_gains_data_gives_small_g`: same fixture with G = 0 → G ≤ 50 W and UA ≈ 150 (rel 0.05).
- `test_gains_at_bound_rejected`: meter scaled so the fit wants G > 3000 → UA None, warning contains "gains at bound".
- `test_prediction_uses_calibrated_gains_only_for_daily`: `_calib` with UA 150, gains_w 1000, method "daily" vs method "hourly" (gains_w ignored) → `_space_heating_kwh` differs by exactly the expected gains term on hours where the clip is inactive.
- `test_recalibrate_ua_stores_gains`.
- Existing Plan D daily tests keep passing with the new 3-tuple (their G = 0 data must still recover UA 80 rel 0.05).
